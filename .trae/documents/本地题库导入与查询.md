# 本地题库导入与查询（Excel / Word）

## Context

当前应用每次答题都必须调用在线 AI（`FloatingWindowService.fetchAnswer` → `OpenAIClient.analyzeQuestion`）。用户希望导入自己的 Excel/Word 题库，答题时先在本题库中检索，命中直接返回答案，减少 API 调用与费用，未命中仍回退 AI。

已确认的需求边界：

- 仅支持 `.xlsx` 与 `.docx`（不引入 Apache POI，避免 APK 增大 10MB+）。
- Excel 自动识别常见表头；Word 支持段落与表格。
- 匹配策略：归一化后的「精确包含匹配」；未命中回退 AI。
- 多次导入累加去重，可清空。

## 总体方案

1. 通过 SAF（`ActivityResultContracts.OpenDocument`）选择文件，复制到 `cacheDir` 临时文件并用 `ZipFile` 读取（零新增依赖，仅用 `java.util.zip` + `XmlPullParser`）。
2. 解析出 `题目 / 答案 / 选项 / 题型`，写入新增的 SQLite 表（`SQLiteOpenHelper`，零依赖，不引入 Room/KSP）。
3. 在 `FloatingWindowService.fetchAnswer` 调用 AI 前增加一次本地检索：命中则直接复用现有格式化/复制/展示逻辑。
4. 设置页新增「本地题库」入口页，支持导入、启用开关、清空、查看题数。

## 新增文件

### 1. `app/src/main/java/com/hwb/aianswerer/data/QuestionBankModels.kt`

- `data class BankQuestion(question, answer, options: List<String>?, questionType: String?)`
- `data class ImportResult(total: Int, added: Int)`，`skipped = total - added`
- `object TextNormalizer { fun normalize(raw: String): String }`
  - 全角 ASCII（`0xFF01..0xFF5E`）转半角，仅保留 `isLetterOrDigit()` 并小写化；汉字原样保留。
  - 单条文本截断到 10000 字符，防止异常文件。

### 2. `app/src/main/java/com/hwb/aianswerer/data/QuestionBankRepository.kt`

`SQLiteOpenHelper` 单例 + `object QuestionBankRepository`（内部 `withContext(Dispatchers.IO)`，Context 用 `MyApplication.getAppContext()`）。

建表（DB 名 `question_bank.db`，version 1；`onUpgrade` 仅做 drop + recreate）：

```sql
CREATE TABLE questions(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    question TEXT NOT NULL,
    normalized TEXT NOT NULL,
    answer TEXT NOT NULL,
    options_json TEXT,
    question_type TEXT
);
CREATE UNIQUE INDEX idx_questions_normalized ON questions(normalized);
```

Repository API：

```kotlin
suspend fun findMatch(text: String): AIAnswer?
suspend fun count(): Int
suspend fun insertAll(questions: List<BankQuestion>): ImportResult  // 累加去重，非清空
suspend fun clear()
```

- 匹配 SQL（`MIN_QUESTION_LEN = 8`，过短题干不参与，避免通用短句误命中）：

```sql
SELECT question, answer, options_json, question_type
FROM questions
WHERE length(normalized) >= 8 AND instr(?, normalized) > 0
ORDER BY length(normalized) DESC, id ASC
LIMIT 1
```

- 命中后组装 `AIAnswer(question, questionType ?: "", answer, options)`；`options_json` 用 Gson 以 `Array<String>` 读写（无需新增 ProGuard 规则）。
- 导入：`beginTransaction()` + `insertWithOnConflict(..., CONFLICT_IGNORE)`，返回 `-1` 计为跳过；`normalized` 唯一索引保证重复导入不重复入库。
- 计数 `SELECT COUNT(*)`；清空 `DELETE FROM questions`。

### 3. `app/src/main/java/com/hwb/aianswerer/data/QuestionBankImporter.kt`

`object QuestionBankImporter`，对外：

```kotlin
suspend fun import(uri: Uri): ImportResult   // withContext(Dispatchers.IO)
```

流程：

1. `contentResolver.openInputStream(uri)` 复制到 `cacheDir` 临时文件，超过 **30MB** 抛错；`finally` 删除。
2. 打开 `ZipFile`，按条目判断类型，不依赖扩展名/MIME：
   - 含 `xl/workbook.xml` → xlsx
   - 含 `word/document.xml` → docx
   - 否则抛「仅支持 .xlsx/.docx」
3. 解析为 `List<BankQuestion>`，空列表抛「未识别到有效题目」。
4. 调用 `QuestionBankRepository.insertAll()` 写入。

#### XLSX 解析

- 先解析 `xl/sharedStrings.xml`：每个 `<si>` 累积所有 `<t>` 文本；进入 `<rPh>` 子树时忽略其文本。
- 再遍历 `xl/worksheets/sheetN.xml`（按 N 数字升序），`XmlPullParser`（关闭命名空间，比较元素时取冒号后的本地名）。
- 单元格：`t="s"` 取共享串；`t="inlineStr"` 取 `<is><t>`；其余取 `<v>` 原文。列号由 `r="AB12"` 的字母折叠计算，缺失列补空串。
- 每个 sheet 独立执行通用表格解析（见下）。

#### 通用表格解析（Excel sheet 与 Word 表格共用）

输入 `List<List<String>>`：

- 表头识别：扫描前 5 个非空行，同一行同时命中「题目别名」和「答案别名」即视为表头；别名（包含匹配）：
  - 题目：`题目`、`问题`、`题干`、`试题`、`question`
  - 答案：`正确答案`、`参考答案`、`答案`、`解析`、`answer`（按此优先级匹配，避免「答案解析」误判）
  - 选项：`选项`、`备选项`、`options`
  - 题型：`题型`、`类型`、`type`
- 无表头兜底：按 `A=题目、B=答案、C=选项、D=题型` 读取（在页面说明中提示用户）。
- 逐行生成：题干、答案均非空才收录；选项单元格按换行 / `|` / `；` 切分；单单元格截断 10000 字符。

#### DOCX 解析

- 读取 `word/document.xml`，用 `XmlPullParser` 状态机（`inTable / inRow / inCell / inParagraph`）：
  - `<w:t>` 累加文本，`<w:tab>` 转空格，`<w:br>/<w:cr>` 转换行。
  - `</w:tc>` 收集单元格；`</w:tr>` 得到一行；表格行交给通用表格解析。
  - 表格外 `</w:p>` 产出一行段落；保留空段落作为分隔标记。
- 表外段落按以下优先级解析：
  1. **前缀模式**（存在 `题目：` / `问题：` / `题干：` / `答案：` / `正确答案：` 前缀时）：前缀行开始新题/填写答案；`A.`~`H.` 开头的行归入选项；其余行归入当前题干或答案。
  2. **空行分块模式**（存在空段落时）：每块第一行是题干，`A.`~`H.` 行为选项，其余行合并为答案。
  3. **两行一组模式**（无前缀且无空行）：连续非空行按「题干、答案」成对读取，末尾落单行丢弃。
- 页面 `InfoCard` 中说明推荐 Word 格式，降低误解析概率。

## 风险与边界

- **解析失败不污染题库**：整份文件解析成功后才在一个事务内写库。
- **OOM**：限制文件 30MB、单元格 10000 字符；全程流式 XML 解析，不使用 DOM。
- **Word 误配对**：优先前缀/表格规则，页眉页脚不解析；无法识别的段落直接跳过。
- **OCR 只识别到部分题干**：包含匹配失败 → 自动回退 AI，不阻断答题。
- **多题同屏**：仍只返回最长匹配的一题（与现有单题 `AIAnswer` 模型一致）。
- **R8**：仅使用 `Array<String>` 的 Gson 读写，无新增反射类，无需改 `proguard-rules.pro`。
- **无存储权限**：SAF 不需要新增权限。
- 数据库 version 1；后续升级按增量迁移处理（本次仅 drop/recreate 占位）。

## 验证

构建：

```powershell
.\gradlew.bat :app:assembleDebug
```

手工端到端：

1. 准备 `sample.xlsx`：首行表头 `题目 / 答案 / 选项 / 题型`，录入 3 道题；另准备无表头两列版本。
2. 准备 `sample.docx`：一份使用 `题目：/答案：` 前缀，一份使用两列表格，一份使用空行分块。
3. 设置 → 本地题库 → 导入，确认题数正确；重复导入同一文件，题数不变（全部计为跳过）。
4. OCR 截取完整题干 → 悬浮窗直接显示题库答案并自动复制，状态显示「题库命中」。
5. 截取部分题干或题库中不存在的题 → 确认回退 AI，行为与旧版一致。
6. 关闭「启用本地题库」→ 再次答题，确认直接走 AI。
7. 清空题库（二次确认）→ 题数归零；重启应用后题数保持不变。
8. 切换英文 → 题库页面文案完整，无中文残留。
9. 导入 `.xls` / 超大文件 / 损坏文件 → 提示明确错误且题数不变。
